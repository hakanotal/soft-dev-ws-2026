# Penguin Data Explorer

A small dataset analysis project. Python analyses `data/penguins.csv` and writes the results as JSON. A simple Vite web page reads that JSON and shows tables and charts. There is no backend server, so the site deploys to GitHub Pages as static files.

## Status

Not scaffolded yet. The first build steps are:

1. Python side: `uv init --bare`, then `uv add pandas` and `uv add --dev pytest`. Create `analysis/__init__.py`, and add this to `pyproject.toml` so tests can import `analysis`:
   ```toml
   [tool.pytest.ini_options]
   pythonpath = ["."]
   ```
2. Web side: `npm create vite@latest web -- --template vanilla --no-interactive`, then create `web/vite.config.js` with `base: './'` so the built site works at any GitHub Pages address:
   ```js
   import { defineConfig } from 'vite'
   export default defineConfig({ base: './' })
   ```

Keep everything below true while scaffolding.

## Stack

- Python managed by uv (never call `pip` or `python` directly, always go through `uv`).
- pandas for analysis, pytest for tests.
- Vite with vanilla JavaScript and plain CSS in `web/`. No framework.
- GitHub Pages for hosting, deployed by a GitHub Actions workflow in `.github/workflows/`.

## Commands

```bash
uv sync                             # install Python dependencies
uv run python -m analysis.analyze   # read data/, write web/public/data/summary.json
uv run pytest                       # run Python tests

npm --prefix web install            # install web dependencies
npm --prefix web run dev            # local dev server
npm --prefix web run build          # production build into web/dist/
```

**Check command** (run before calling any task done): `uv run pytest && npm --prefix web run build`

## Layout

- `data/penguins.csv`: the raw dataset. Read it, never edit it. See `data/README.md` for columns.
- `analysis/`: Python code. Pure functions that take a DataFrame and return plain data, plus `analyze.py` which wires them together and writes JSON.
- `tests/`: pytest tests, one file per module in `analysis/`.
- `web/`: the Vite app. It only reads `web/public/data/*.json` and never does analysis itself. Fetch data with relative paths (`./data/summary.json`), never with a leading `/`, or it breaks on GitHub Pages.
- `web/public/data/summary.json`: generated by `analyze.py`. Committed so the site builds and deploys without Python. Regenerate it after changing the analysis.
- `docs/`: workshop material for humans.
- `.github/workflows/deploy.yml`: builds `web/` and publishes it to GitHub Pages on every push to `main` that changes `web/`. It runs `npm ci`, so `web/package-lock.json` must be committed (commit `uv.lock` too).

## Conventions

- Keep tasks small. One feature per branch, one commit per working step.
- Every analysis function gets a test. Write the test first when fixing a bug.
- Handle missing values (`NA` in the CSV) explicitly and say how in the function's test.
- Ask before adding a dependency, and confirm the package exists on pypi.org or npmjs.com first.
- Look up library APIs (pandas, Vite) with Context7 rather than guessing.
- Never use em dashes in anything you write: code, comments, docs or commit messages. Use a comma, a colon, brackets or a full stop.
- Commit messages: short imperative subject, for example `Add species summary table`.

## Do not touch

- `.env` and anything that looks like a secret. Use `.env.example` for variable names.
- `data/penguins.csv`.
- `.github/workflows/` and `.claude/settings.json`, unless asked.
